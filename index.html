What it does

Text, files, and folders

Encrypt a short message, a single file, or an entire folder, all from the same interface.

AES-256-GCM

Authenticated encryption — a wrong password or tampered data is detected, not silently turned into garbage.

PBKDF2 key derivation

600,000 iterations of PBKDF2-HMAC-SHA256 with a fresh random salt for every file.

Password or key file

Unlock with a passphrase, or use any file on disk as your key instead.

Secure shred

Overwrite a file or folder with random data — 1 to 5 passes — before deleting it.

File hashing

SHA-256, SHA-512, SHA-384, SHA-1, or MD5 — pick the algorithm, get the digest.

How it works

Every file starts with a random 16-byte salt, then a series of chunks — each one a fresh 12-byte nonce, the AES-256-GCM ciphertext, and a 16-byte authentication tag. Text payloads use the same layout, just base64-encoded instead of written to disk.

Folders get packed into a small custom archive — relative path, size, and bytes for every file — which then gets encrypted the same way a single file would.

On Windows, the crypto runs through the OS's own CNG API (bcrypt.h) — no OpenSSL dependency to install. On Linux and macOS it uses OpenSSL.

Before you rely on it

This is a hobby project and has not been independently audited. Don't use it as the only copy of anything important.

Secure shredding overwrites a file's contents, but on SSDs, journaling filesystems, or synced folders (OneDrive, Dropbox), old copies may still exist elsewhere — it isn't a guarantee of unrecoverable deletion.

There's no password recovery. Lose the password or key file, and the data is gone for good.
